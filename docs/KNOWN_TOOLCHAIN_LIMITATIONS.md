# Известные ограничения инструментов

Проверено с KiCad 10.0.4, tscircuit 0.0.2097 и `circuit-json-to-kicad` 0.0.163.

## Конвертация в KiCad

Конвертер создаёт встроенную геометрию символов и footprints, но записывает им служебные библиотеки `Custom`, `Device` и `tscircuit`. Локальная таблица библиотек KiCad таких имён не содержит, поэтому полный аудит сообщает `lib_symbol_issues` и `lib_footprint_issues` даже при наличии геометрии внутри файла.

Схематические координаты конвертера могут не совпадать со стандартной сеткой KiCad, что вызывает `endpoint_off_grid`. Подписи footprints размером 0,4 мм могут вызывать `text_height` при стандартном минимуме KiCad 0,8 мм.

## Нумерация source-портов и pads

У diode-примитива tscircuit в Circuit JSON `pin1=anode`, `pin2=cathode`, тогда как
распространённая конвенция KiCad для diode footprints — `pad 1=K`, `pad 2=A`.
Кроме того, GCT USB4105 и Alps EC11E используют именованные pads. ERC схемы не
проверяет это сопоставление. До PCB release требуется явный pin-to-pad adapter,
сравнение с package drawing и визуальная проверка каждого pad; сейчас это
отмечено `BLOCKED_PAD_MAPPING`.

В версии `circuit-json-to-kicad` 0.0.163 автоматические rail/ground net labels
экспортируются как custom symbols, вывод которых смещается от anchor и вызывает
ложный `pin_not_connected`. Генератор преобразует только такие представления в
глобальные метки с тем же именем и anchor. Электрические имена сетей не меняются;
этот workaround нужно повторно проверить при обновлении конвертера.

Та же версия не экспортирует tscircuit `noConnect` в KiCad и задаёт всем выводам
generic chip тип `passive`. Генератор воспроизводимо меняет тип только явно
перечисленных неиспользуемых выводов ESP32-C3 и USB SBU на KiCad `no_connect`.
Если pinout или конвертер изменится, генерация остановится, а не промолчит.

Эти предупреждения сохраняются командами `npm run audit` в `build/reports/*-all.json`. Они не скрываются и должны повторно оцениваться после обновления конвертера.

Конвертер формально поддерживает tscircuit `schematicsheet`, но в версии 0.0.163
символы переносятся на дочерние листы, а часть wires и labels остаётся на корневом
листе. Проверочный многолистовый экспорт дал 98 ERC-ошибок, поэтому текущий выпуск
использует один структурированный лист A2. Возможность иерархии нужно проверить
повторно после обновления конвертера.

Автоматически выбранные координаты также не дают профессиональной компоновки.
Принадлежность функциональным блокам и координаты задаются в `src/board.tsx`.
`src/generate.tsx` заменяет только межблочные page-spanning traces короткими
отводами с глобальными labels, добавляет title block и сохраняет единственный
лист. Короткие внутриблочные wires остаются физическими. Ручная правка
сгенерированного листа будет потеряна.

## Политика проверок

На текущем этапе `routingDisabled`: PCB и корпус исключены из задачи. Поэтому
полный `npm run verify` после успешного ERC закономерно останавливается на DRC с
unconnected items. Эти ошибки нельзя игнорировать или выдавать за пройденный DRC;
они закрываются реальной разводкой только на этапе PCB.

- `npm run erc` и `npm run drc` завершаются ошибкой при нарушениях уровня `error`.
- `npm run audit` сохраняет ошибки и предупреждения для инженерного просмотра.
- Предупреждение реального проекта нельзя исключать только потому, что оно похоже на известное ограничение: нужно проверить тип и затронутый элемент.
- Перед производством необходим просмотр исходной схемы, платы и Gerber в KiCad или независимом viewer.
